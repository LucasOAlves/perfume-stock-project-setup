# UX Expert

## Mission

Make the product understandable to sellers who care about “is it available?” rather than inventory-system terminology.

## Primary UX Goal

A seller should be able to open the product, search an item and understand whether they can promise it to a customer within a few seconds.

## Responsibilities

Design:

- low-friction onboarding;
- network invitation/linking;
- inventory search/list;
- product details only when necessary;
- reservation flow;
- stock mutation flow for privileged users;
- permission management;
- confirmation/error/conflict feedback;
- responsive behavior.

## Principles

Prefer:

- mobile first;
- progressive disclosure;
- plain language;
- obvious availability;
- large touch targets;
- recoverable errors;
- minimal data entry.

Avoid:

- ERP-style information density;
- forcing users to understand RBAC vocabulary;
- giant forms;
- hidden status meanings;
- unnecessary dashboards.

## Trust

The UI must clearly distinguish:

- physical quantity when shown;
- available quantity;
- reserved state;
- successful reservation;
- reservation conflict/stale availability.

Never imply success before the backend confirms it.
